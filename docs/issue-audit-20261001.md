## 主动天赋导入故障的原因

调用链：米游社快照 → createMysConverter.character → 保存预设 → “我的角色”加载 → useCharacter → 公共伤害接口。

旧转换器先筛选 skill_type=1，再按完整名称匹配目录的三项天赋。只要没有全部匹配，就退回主动列表，并要求长度恰好为 3。

合成数据已实际复现以下组合：

- 普攻名为“因果点破”／“神里流·倾”，目录含“普通攻击·”前缀。
- 列表另有“虚实流动”／“神里流·霰步”，因此有四项主动技能。
- 名称未完全匹配后退回四项列表，两个角色都抛出“无法确定三个主动天赋的对应关系”。
- 即便只有三项，按数组顺序回退仍有乱序等级被填错字段的风险。
- 没有已保存预设时，旧角色摘要直接取主动列表前三项，可能把冲刺等级显示为战技／爆发等级。

这是可复现的代码问题；未拿到用户原始快照，不能据此断言其服务器响应的每个字段与合成样例完全一致。

## 共用修复

新增 src/import/character-talents.mjs：

1. 规范 Unicode 字形、空白、常见中点以及“普通攻击·”／“Normal Attack:”前缀。
2. 按目录的普攻、战技、爆发名称分别唯一匹配，不依赖列表顺序或总长度。
3. 额外技能不占用三个天赋字段；仍校验主动技能类型。
4. 缺少名称、重复匹配、非法等级时提示具体天赋与原因，取消不可靠的位置回退。

src/import/miyoushe.mjs 使用共享解析生成预设；src/import/character-summary.mjs 在无可用预设时使用同一规则生成摘要，匹配不明显示“—”并保留原因。没有给莫娜、绫华或其他角色建立专用名单。

已有预设仍优先显示已保存数值。同步失败继续保留原有可用预设，本轮不批量修改存档。更新版本后重新同步或重新导入原始米游社快照，才会重新解析等级；直接导入此前已转换的 UID 包不会自动重算其保存的天赋字段。
