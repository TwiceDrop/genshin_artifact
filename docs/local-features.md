# 本地版：收益曲线与米游社导入

## 启动

已在 Windows、Node.js 24.19.0 验证。首次构建需要 Node.js 20+、Git 和 7-Zip（默认 `C:/Program Files/7-Zip/7z.exe`，可通过 `SEVEN_ZIP` 指定）。

```powershell
npm ci --legacy-peer-deps
npm run setup:release
npm run test:local
npm run build:local
npm start
```

打开 **http://127.0.0.1:4174/#/calculate**。以后只需 `npm start`；修改前端后重新 `npm run build:local`。保持该终端运行。`MONA_PORT` 可修改监听端口，但浏览器存储按访问地址隔离，换端口或 localhost/127.0.0.1 会进入不同的存储空间。

这是本地网页加本机服务，尚未重新打包为 Tauri EXE。原 `npm run serve` 仅用于前端开发，米游社功能请在上述本机地址验证。

## 米游社导入

1. 在计算页角色选择上方点击「米游社导入」。
2. 点击「米游社扫码登录」，用米游社 App 扫码并在手机确认。确认页可能显示米游社或 HoYoPlay。登录后 Cookie 自动加密保存；再次打开会恢复最近使用的账号，无需重复扫码。
3. 选择当前账号绑定的国服原神 UID，点击「同步全部角色」。支持官服及渠道服；不支持国际服 HoYoLAB。
4. 选择「用于计算」或计算页「我的角色」，自动加载等级、突破、命座、显示天赋等级、武器等级/突破/精炼和五个装备槽位。

「我的角色」使用元素标签页选择窗口，顶部为全部及七种元素。每行左侧展示立绘、角色名称、元素图标、武器类型和命座；右侧展示天赋、当前四件套（未凑齐显示“无”）、武器名称/精炼/等级。点击整行加载角色，导入窗口的已保存角色列表使用相同布局。天赋和装备摘要读取将要加载的预设及实际装备记录。

「Cookie 账号管理」支持多个米游社账号，点击「使用」切换；「扫码添加 / 更新账号」会更新同一米游社 ID 的凭证，不增加重复账号。「手动录入 Cookie」支持 v1/v2，验证绑定角色后保存，可使用本人已在 genshin-plugin 验证可用的 Cookie。完整 Cookie 不会通过列表或快照接口返回。

Cookie **无本地自动删除期限**。关闭窗口、取消同步、刷新或重启服务都保留；上游凭证失效会标记需要更新，5003 等错误也不会删除账号。「删除 Cookie」才会移除指定账号凭证并使它的本机连接失效；已导入角色、预设和圣遗物不受影响。删除本机凭证不等于注销米游社服务器上的登录。

来源接口是本人战绩的完整角色列表与角色详情，不要求把所有角色放进公开展示柜。**米游社只提供角色已装备的圣遗物，无法借此取得未装备的背包圣遗物**，后者仍需 YAS/OCR。

数据保存在当前莫娜账号的 IndexedDB，并参与原有文件同步/备份。每个 UID 保留一份无凭证的角色原始快照，可导出并离线恢复。已知角色写为独立的米游社预设；重复同步更新养成数据，保留该预设中既有计算条件。不会覆盖同名手工预设。

去重按套装、部位、星级、强化等级、主副词条最终值匹配。副词条顺序不影响结果。同一次同步中两件数值完全一样的圣遗物仍保留两份；同一份快照重复导入不增加件数。接口没有背包物品唯一 ID，无法证明“强化前后是同一件”，因此数值变化会保留旧记录并新增/匹配当前装备，不删除旧库存。这是快照去重，不是背包实时镜像。

未知角色、武器、套装、无效属性或无法确认突破状态的条目会显示待适配原因并保留原始数据，不会用默认值悄悄替代。缺失详情会明确报告。天赋采用米游社显示等级，含命座增加的等级，再转为莫娜的从零开始索引；莫娜内核不另加 C3/C5 天赋等级。

队伍增益、武器层数、圣遗物触发条件和敌人参数仍需在计算页确认；米游社没有提供完整的战斗情境。

### 登录实现与范围

扫码模块直接使用用户指定的 [TwiceDrop/mhy-qdcode-to-cookie](https://github.com/TwiceDrop/mhy-qdcode-to-cookie)，固定提交 `1813583f97548fb7b9afddead548b13f92d4106a`，来源及 GPL-3.0 许可证位于 `server/vendor/twicedrop/`。导入接口参考 [TRSS Yunzai-genshin 的 apiTool](https://github.com/TimeRainStarSky/Yunzai-genshin/blob/main/model/mys/apiTool.js)；角色详情字段参考 [miao-plugin MysPanelData](https://github.com/yoimiya-kokomi/miao-plugin/blob/master/models/serv/api/MysPanelData.js)。

本机服务只监听回环地址，不上传给额外的中转服务器。二维码有效期最多 120 秒。凭证保存在项目的 `.local-data/miyoushe.dpapi`，由 Windows DPAPI 当前用户加密，已排除 Git；不能直接复制到另一 Windows 用户使用。凭证不打印日志、不写角色快照，SToken 不持久保存。浏览器与服务的临时连接仍可过期，但只需重新选择已保存账号，不会删除 Cookie。不会执行签到、聊天、兑换等账号写入操作。接口如果要求验证，由用户在米游社 App 完成后重试。

战绩读取前按 TRSS 的兼容设备参数调用官方 `device-fp/api/getFp`，要求外层成功且内层 `code=200`，随后在角色列表和详情请求携带返回的 `x-rpc-device_fp`。设备 ID、seed 和指纹随账号加密保留；设备初始化不发送登录 Cookie。5003 会标明失败阶段，不能仅凭该错误码判断是 Cookie 失效或验证码；1034 单独提示要求验证。不会自动反复重试被拒绝的请求。

验证范围：真实账号扫码确认、绑定 UID 查询以及官方设备初始化已通过；角色读取曾返回 5003，补齐设备请求头后仍需真实账号复测完整同步。模拟响应测试不等于实际账号成功。持久存储测试覆盖 Windows DPAPI 加解密、服务重启恢复、同账号更新、失败不删除、显式删除与会话失效；独立测试页面也验证了手动保存、关闭重开、页面刷新恢复及删除。

浏览器验证使用 `tests/fixtures/miyoushe-synthetic.json` 的合成数据（非真实账号）：桑多涅、奥黛塔、阿罗夏和砂糖共 4 名角色/20 件装备。首次导入新增 20 件，重复导入新增 0 件并复用 20 件；刷新后角色仍可选择并加载五件套、天赋和武器，桑多涅星超导曲线正常显示。测试使用独立的 localhost 存储，日常使用上述 127.0.0.1 地址不会载入这些测试数据。

## 0–20 词条最优收益曲线

计算页 BUFF 区直接提供「启用极星辉域」和「极星辉域层数」（0～12）。它与「添加 BUFF → 元素共鸣 → 极星辉域」使用同一份原生配置，编辑时合并同名条目，避免重复加成。关闭开关保留层数但不应用效果；保存/载入预设也会保留开关和层数。伤害面板、圣遗物优化及收益曲线都使用此配置。内核实测的桑多涅固定测试配置在 0/6/12 层时星超导期望分别为 796.46/1353.99/1592.93，此数值只用于回归验证，不代表用户账号伤害。

计算页选择角色、装备、技能及计算条件后，点击「最优收益曲线 · 0～20 条」。

- 横轴为新增五星副词条次数，0 为当前配置。每个预算单独穷举最优分配，允许 3 条和 4 条时最优组合发生整体变化。
- 默认暴击率、暴击伤害、攻击百分比、元素精通；可选择其他副属性。每条数值可用四档平均值或最高档。
- 图上查看总提升或目标伤害，下图显示相对前一个预算的增量；点击曲线或移动滑块查看分配次数、属性增量和最终面板。
- 使用当前莫娜伤害内核重新计算每个候选，保留四件套、武器、技能、敌人和已设置增益；不是固定词条评分相加。
- 本功能模拟当前配置额外获得属性的理论收益，不保证这些词条能实际分配到五件圣遗物，不替换或修改库存，也不做四人队轮转优化。
- 零伤害基线只显示伤害值，不伪造百分比；取消会终止 Worker。输入改变后结果失效，完整结果可导出 JSON。
- 默认四属性共 10,626 个候选。为避免过久等待，超过 100 万候选会明确拒绝，请减少属性种类；不会截断后声称全局最优。

## 圣遗物详情与喵喵评分

套装的两件/四件效果参数按套装分别保存。修复了从黑曜秘典切换到深廊终曲时，两件套监听器清空四件套配置，导致丝柯克页面中间整列不显示且面板可能残留旧值的问题。回归测试覆盖切套、空槽、两件套参数传递以及丝柯克原生伤害计算。

在仓库点击圣遗物卡片即可查看完整主副词条、逐条得分和全部适配角色的评分排名；可以搜索角色并点击查看对应词条贡献。普通评分沿用 BetterGI ArtifactScore 的前 50% 角色均分。

计算器中，点击已装备圣遗物打开同一详情窗口，默认使用当前角色配置。五件卡片各自显示分数与评级，上方实时显示总分和圣遗物毕业度。更换装备仍可从详情窗口的「更换此部位圣遗物」进入；空槽仍点击加号。删除、编辑、锁定按钮不触发详情。

「已保存的角色」和「我的角色」按昵称、UID 分组，点击 UID 查看对应角色，再按元素筛选。UID 选择随莫娜账号保存；新增或同步一个 UID 保留其他 UID 的角色、预设与装备。同步暂时缺失或解析失败的角色，如有已保存预设则提示使用旧数据，仍允许选择。

圣遗物对比支持开关及三种基准：「游戏内穿戴」为所选 UID/角色最近一次同步的装备快照；「此次计算前」为本轮开始计算前的五件装备；「对比历史」可选择以前保存的配装。比较同时检查装备 ID 和词条内容，在各部位标记「已替换」「新增」或「已卸下」。游戏记录独立于可编辑的计算预设，保存计算器配装不会覆盖游戏内记录。

计算前穿戴及查看过的结果自动进入历史，也可以手动保存当前配装。历史按莫娜账号、UID、角色隔离，每个角色保留最近 50 份，刷新后保留；查看历史只切换对比基准，不直接替换穿戴。切换角色、载入预设或切换莫娜账号清除本次计算基准，历史仍保留。

面板随对比基准显示黑色旧值 → 当前值（差值），增长为红色、下降为绿色，百分比差值按百分点直接相减，例如 97.3% → 96.3%（-1.0%）。新旧两套均按当前角色、武器、BUFF 与套装参数重新计算，只比较圣遗物差异；关闭对比或没有可用基准时显示普通面板。

评级按五件平均分：S ≥28、SS ≥35、SSS ≥42、ACE ≥49、MAX ≥56（总分分别为 140、175、210、245、280）。不足五件显示「未齐装」，未配置规则的角色显示「待适配」。这是圣遗物词条质量评级，不包含天赋、角色等级或武器养成的综合毕业评价。低星/未满级按当前词条使用五星评级标准，不预测强化。

来源固定为 [BetterGI ArtifactScore 1.8.0](https://github.com/babalae/bettergi-scripts-list/tree/22d10e633fc9e03385b7766a66772d9a1aad2936/repo/js/ArtifactScore)，角色权重与特殊规则来自 miao-plugin。默认角色排名与当前角色定向评分分开：定向评分传入命座、武器名称/精炼、当前面板与四件套名称。只应用源规则中已有的套装条件，不额外捏造套装分。适配、来源记录和上游使用说明见 `src/algorithms/artifact-score/vendor/README.md`。

## 自动配装穿戴保护

自动配装的“开始计算”下方有“是否允许替换其他角色已穿戴的圣遗物”开关，默认关闭，随当前莫娜账号在本机保存。关闭时按当前 UID 最近导入／同步的角色穿戴编号排除其他角色装备，保留本角色装备与未被占用的候选；开启后恢复原有候选范围。原有锁定、主词条等筛选仍然有效。保护依据游戏穿戴记录，不将修改后的计算预设视为实际穿戴；没有 UID 记录时无法判断归属。更改开关会清除旧计算结果列表，需重新计算，当前展示的配装不自动回退。

## 角色 BUFF 分组

在“选择 BUFF → 角色引发的 BUFF”中，可通过角色下拉框定位，或展开角色分组，再逐条添加需要的 BUFF。添加后窗口保持打开，已添加项目标记为“已添加”。武器、圣遗物、共鸣和自定义入口保持原有方式。

角色参数区右侧的“添加全部可用 BUFF”按当前命座一次添加尚未加入的效果，保留逐条调整的参数，跳过未解锁和已添加项。计算页中的已添加角色 BUFF 也按角色折叠显示，标题显示总数和启用数；展开后仍可逐条修改参数、停用或删除。折叠不会改变 BUFF 是否参与计算。

有已保存角色时，可选择来源 UID，自动读取该 UID 对应角色的命座和天赋；也可临时手动调整，不覆盖已保存角色。命座不足的独立 BUFF 会显示所需命座并禁止添加。已确认对应关系的天赋与命座参数在添加时自动绑定，其他参数可展开“调整 BUFF 参数”设置。角色归属和命座门槛记录在 `src/algorithms/buff-groups/ownership.json`，测试检查当前内核全部角色 BUFF 的覆盖。

天赋采用游戏显示等级，手动修改命座后需按需调整天赋等级。突破被动、触发状态、队伍条件和来源角色的攻击力、精通等仍需自行确认；不会把已解锁的所有 BUFF 自动当作生效。更改分组中的参数只作用于新添加的 BUFF，已经加入计算器的项目在计算页调整。
