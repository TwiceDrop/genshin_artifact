# 06: 客户端登录页支持密码登录和注册

**What to build:** 登录页可以在「密码登录」和「验证码登录」之间切换。注册填写邮箱、验证码、用户名、密码和确认密码，并说明注册或登录即视为同意用户协议和隐私政策。

现有登录页见 `docs/specs/login-page/spec.md`，登录门在 `src/platform/login-gate.mjs`。

## Comments

- 2026-11-18：已实现。协议草稿还要开发者审定，所以 Status 仍是 `ready-for-human`。
  - 登录页 `src/pages/LoginPage/LoginPage.vue`：默认「密码登录」，可以切到「验证码登录」，另有「注册账号」和「重设密码」两个表单。验证码登录返回 404 `ACCOUNT_NOT_FOUND` 时，直接转到注册表单，邮箱、`challengeId` 和验证码原样带过去。重设成功后回到密码登录，账号一栏填好邮箱。还没有用户名的老账号登录后，仍先到「设置用户名」。
  - 客户端只核对两次密码是否一致。其他错误原样显示服务端的提示，包括密码长度、用户名规则、用户名或邮箱已被使用、验证码错误和限流。
  - 转发：`server/cloud.mjs` 的白名单和 Android 的 `src/platform/cloud-mobile.mjs` 放行 `v1/auth/register`、`v1/auth/password/login`、`v1/auth/password/reset`。前两个成功时，和 `email/verify` 一样在本机保存会话，不把令牌交给页面。重设密码不会登录，所以不保存会话。`src/platform/cloud.mjs` 的 `changed()` 名单也加上了这三个路径。
  - 云档案同步：`src/platform/login-gate.mjs` 新增 `followCloudSession(sync)`，由 `src/router/router.js` 在第一次跳转时接上 `profileSync`，已登录就调 `start()`。之后每次收到 `mona-cloud-context-change`（登录、注册、重设密码、退出、会话失效）都重新读一次 `config`：已登录就 `start()`，已退出就 `stop()`。在线账号页里的退出登录也会因此停掉同步，那个页面不用改。确认登录状态或启动失败时，写进控制台并保持原状。
  - 协议草稿：`public/legal/terms.html`、`public/legal/privacy.html`，顶部注明「草稿，待开发者审定」。内容按 `online-service/` 的实际实现写。除任务要求的几项外，还如实写了：登录会话会记设备名称和时间；验证码加密后短时保存；限流记录含 IP，约一天后删除；使用统计带平台、版本号和随机生成的安装编号，不保存 IP。
  - 测试：`tests/login-routes.test.mjs`，覆盖桌面网关和 Android 对三个新路径的转发与会话保存，以及同步随登录状态启停。
  - 最终文案：
    - 切换：「密码登录」「验证码登录」
    - 密码登录：输入框「邮箱或用户名」「密码」；按钮「登录」；链接「忘记密码」「注册账号」
    - 验证码登录：沿用「邮箱」「验证码」「发送验证码」「N 秒后重发」；按钮由「注册／登录」改为「登录」；链接「注册账号」
    - 未注册的邮箱转到注册时的提示：「该邮箱尚未注册，设置用户名和密码即可完成注册」
    - 注册：标题「注册账号」；输入框「邮箱」「验证码」「用户名（2–16 个字）」「密码（8–64 个字符）」「再次输入密码」；按钮「注册」；链接「已有账号，去登录」
    - 重设密码：标题「重设密码」；输入框「邮箱」「验证码」「新密码（8–64 个字符）」「再次输入密码」；按钮「重设密码」；链接「返回登录」；成功提示「密码已重设，请用新密码登录」
    - 两次密码不一致：「两次输入的密码不一致」
    - 协议提示（登录和注册按钮下方，重设密码表单不显示）：「登录或注册即表示同意《用户协议》和《隐私政策》」，两个书名号分别链接到草稿页，在新窗口打开
  - 待实测：桌面和手机宽度各一次（本次只核对了源码、单元测试和组件能否编译）；协议链接在 Tauri 窗口和 Android WebView 里用 `target=_blank` 能否正常打开。
  - 顺手发现，没有改：`profile-sync-core.mjs` 的 `init()` 没等 `accountReady` 就读账号名（`names = accountNames()`）。现在同步在打开软件时就启动，如果账号仓库还没加载完，第一次改名可能检测不到。
