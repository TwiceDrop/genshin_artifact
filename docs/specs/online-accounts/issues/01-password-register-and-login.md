# 01: 服务端支持密码注册和密码登录

**What to build:** 注册时用邮箱验证码 + 用户名 + 密码建号；登录可以用「邮箱或用户名 + 密码」，也可以继续用邮箱验证码。

现状：只有验证码登录（`online-service/src/auth.mjs` 的 `requestCode`、`verifyCode`），验证成功时自动建号，`users` 表没有密码。用户名已有（`005_usernames.sql`，不区分大小写唯一）。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 迁移：`users` 增加密码哈希字段。哈希用 `node:crypto` 的 scrypt 加随机盐，不新增依赖
- [x] 注册接口：校验验证码，同时写入用户名和密码，用户名规则沿用 `setUsername`；邮箱或用户名已占用时报错
- [x] 验证码登录不再自动建号，邮箱未注册时报错。规格要求每个账号都有密码
- [x] 密码登录接口：按邮箱或用户名找账号，校验密码后签发会话，会话格式与验证码登录相同。错误提示不区分「账号不存在」和「密码错误」
- [x] 限流：密码登录同一 IP 每小时 20 次（原稿要求），另加按账号计数的限流，沿用 `limit()`
- [x] 测试：注册、两种登录、用户名登录不区分大小写、限流、未注册邮箱用验证码登录被拒

## Comments

- 2026-11-18：已实现。
  - 接口：`POST /v1/auth/register`（`challengeId`、`code`、`username`、`password`、`deviceName`），以及 `POST /v1/auth/password/login`（`account` 填邮箱或用户名、`password`、`deviceName`）。两者的返回格式都和验证码登录一样。
  - 迁移：`006_passwords.sql`。
  - 密码规则：8–64 个字符，不限字符种类，首尾空格保留（开发者确认）。
  - 限流：同一 IP 每小时 20 次，同一账号每小时 10 次。账号按解析出的用户计数，所以用邮箱和用户名登录共用同一个额度。
  - 用验证码登录未注册的邮箱时返回 404 `ACCOUNT_NOT_FOUND`，不消耗这个验证码，客户端可以拿同一个验证码接着注册。
  - 密码哈希：scrypt，参数为 N=2^15、r=8、p=1，参数写进哈希串，以后可以调高。账号不存在时也做一次同等开销的计算，避免通过响应时间判断账号是否存在。
- 影响：
  - 测试夹具的 `login()` 改为「未注册就先注册」。
  - `username.test.mjs` 里「用户名初始为空」的断言改为「注册时已设定」。
  - 客户端登录页（`login-page`）现在只会用验证码登录，新用户在任务 06 完成前无法通过客户端注册。
  - 客户端「首次登录后询问用户名」对新账号不会再出现。
