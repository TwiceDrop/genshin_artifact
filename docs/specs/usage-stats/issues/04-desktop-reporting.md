# 04: 桌面端上报主链路

**What to build:** 桌面客户端打开任何页面，都会按天记录一次对应的入口访问，并经本机服务批量发到在线服务；断网时记录先存在本地，恢复后补发。上报地址的构建常量为空时，整套使用统计不启用。

**Blocked by:** 01, 02

**Status:** ready-for-agent

规格见 `docs/specs/usage-stats/spec.md` 的「客户端的使用统计模块」和「发送通道」。

- [ ] 客户端使用统计模块：对外只有"记录功能 ID"和"发送队列"两个操作；存储、网络发送、时钟、开关状态和上报地址都由调用方注入
- [ ] 传入未登记的功能 ID 时直接报错，不静默忽略
- [ ] 本地队列按"功能 ID + 日期"去重；只保留最近 30 天、最多 500 条，超出时丢最早的
- [ ] 第一次需要时在本地生成匿名安装 ID
- [ ] 启动时、每 10 分钟、退出时各批量发送一次；失败的记录留在队列里下次重试；发送失败不弹提示、不阻塞界面
- [ ] 本地只保留最近一次发送失败的阶段、原因和时间，附在配装页和四人轴页现有 Debug 导出的环境信息里；不新做全局导出入口（2026-11-12 开发者确认）
- [ ] 上报地址写成构建常量，和玩家填写的在线账号地址无关；常量为空时模块不启用，开发版和测试默认为空
- [ ] 本机服务新增一条独立的转发路径，做法和在线账号转发相同，不复用在线账号的会话或凭据
- [ ] 一个全局路由钩子统一记录入口访问，页面里不单独记录
- [ ] 模块测试注入内存存储、假网络和假时钟，覆盖：同一天去重、跨天重新入队、失败保留并重试、30 天和 500 条上限、常量为空时不启用、失败信息出现在 Debug 导出的环境信息里
- [ ] 验证：只跑模块测试；再用本地运行的在线服务实测一次桌面端打开页面后库里出现记录，汇报时写清是本地服务
