# 04: 桌面端上报主链路

**What to build:** 桌面客户端打开任何页面，都会按天记录一次对应的入口访问，并经本机服务批量发到在线服务；断网时记录先存在本地，恢复后补发。上报地址的构建常量为空时，整套使用统计不启用。

**Blocked by:** 01, 02

**Status:** done

规格见 `docs/specs/usage-stats/spec.md` 的「客户端的使用统计模块」和「发送通道」。

- [x] 客户端使用统计模块：对外只有"记录功能 ID"和"发送队列"两个操作；存储、网络发送、时钟、开关状态和上报地址都由调用方注入
- [x] 传入未登记的功能 ID 时直接报错，不静默忽略
- [x] 本地队列按"功能 ID + 日期"去重；只保留最近 30 天、最多 500 条，超出时丢最早的
- [x] 第一次需要时在本地生成匿名安装 ID
- [x] 启动时、每 10 分钟、退出时各批量发送一次；失败的记录留在队列里下次重试；发送失败不弹提示、不阻塞界面
- [x] 本地只保留最近一次发送失败的阶段、原因和时间，附在配装页和四人轴页现有 Debug 导出的环境信息里；不新做全局导出入口（2026-11-12 开发者确认）
- [x] 上报地址写成构建常量，和玩家填写的在线账号地址无关；常量为空时模块不启用，开发版和测试默认为空
- [x] 本机服务新增一条独立的转发路径，做法和在线账号转发相同，不复用在线账号的会话或凭据
- [x] 一个全局路由钩子统一记录入口访问，页面里不单独记录
- [x] 模块测试注入内存存储、假网络和假时钟，覆盖：同一天去重、跨天重新入队、失败保留并重试、30 天和 500 条上限、常量为空时不启用、失败信息出现在 Debug 导出的环境信息里
- [x] 验证：只跑模块测试；再用本地运行的在线服务实测一次桌面端打开页面后库里出现记录，汇报时写清是本地服务

## Comments

- 2026-11-12：模块分三层。`src/usage-stats/recorder.mjs` 是可注入依赖的核心；`install.mjs` 挂路由钩子和发送时机；`index.mjs` 选择存储、平台和发送方式。桌面发送在 `src/platform/usage-stats-transport.mjs`，本机服务的转发在 `server/usage-stats-forward.mjs`，只接受 https，或本机回环地址上的 http。
- **和规格不同、需要开发者决定的一处**：服务端只接受和当天相差 2 天以内的日期（02 已确认），所以客户端会丢弃超过 2 天的记录，离线补发实际上只覆盖 2 天，而不是 30 天。要恢复 30 天，把登记模块里 `USAGE_UPLOAD_RULES.dayTolerance` 改成 30，客户端和服务端会一起生效。因为只能存 2 天，500 条的队列上限实际碰不到，所以只在发送时按 500 条切批。
- 规格里写的是"同一天同一功能只入队一次"。为此另外记了一份"今天已发送"，按同一个日期窗口清理，发过的不再重新入队。
- 退出时用 `keepalive` 发送：服务端能收到，但页面已经卸载，拿不到响应，队列要等下次启动再发一遍。服务端按天去重，重复发送不会多算。
- 构建常量是 `MONA_USAGE_STATS_URL`，两个环境文件里都是空字符串。Android 构建在 05 之前不启用。
- Debug 导出：配装页的导出在 `environment.usageStats` 里，四人轴的导出在顶层 `usageStats` 里。内容是是否启用、排队条数、最近一次发送时间、最近一次失败（阶段、原因、状态码、时间）；不包含匿名安装 ID，避免 Debug 包和统计记录被关联起来。
- 验证：
  - 根目录 `usage-stats-recorder`、`usage-stats-install`、`usage-stats-features` 共 16 项测试通过。
  - 在线服务新增的端到端测试 2 项通过（记录模块 → 桌面发送 → 本机服务 → 在线服务 → 数据库）；上报接口的 4 项测试重跑通过。
  - 用一个测试用的环境文件（上报地址指向本机 4198）构建前端，输出到 `.cache/test/usage-stats/dist`，原有的 `dist/` 没动。在浏览器里切换了 4 个页面：两次 `POST /api/usage-stats` 都是 200，队列清空，没有失败记录。这次实测的是本机服务加合成数据，没有在 Tauri 安装包里跑。
- 2026-11-12（后续）：开发者决定把离线补发放宽到 30 天。日期规则拆成两个上限：过去最多 30 天，未来仍然最多 2 天，客户端保留 0～29 天前的记录，少留一天是因为 UTC 以西的玩家本地日期会比服务器晚一天；同时补上了 500 条上限，超出时丢掉最早的。上面那条"离线补发只覆盖 2 天"的说明已经不再适用。
- 2026-11-12：开发者确认保留本地队列损坏时的处理：记一条存储失败（会出现在 Debug 导出里），然后用空队列继续。
