# 02: 在线服务接收上报

**What to build:** 在线服务能接收客户端发来的使用统计：校验通过的记录按"匿名安装 ID + 功能 ID + 日期 + 平台 + 版本"去重入库，并同步更新累计汇总；不合格的请求被拒绝并返回原因；同一个 IP 发得太频繁会被限流。

**Blocked by:** 01

**Status:** ready-for-agent

规格见 `docs/specs/usage-stats/spec.md` 的「在线服务」。2026-11-12 开发者已确认下面的校验规则。

- [ ] 在线服务里新增一个独立的使用统计模块，不读写账号、会话、Cookie 托管和快照相关的表
- [ ] 新增迁移文件，接在现有迁移之后：一张明细表（上面五个字段唯一），一张累计汇总表（按功能、平台、版本记录用过的安装数）
- [ ] 上报接口：一次请求带一个匿名安装 ID、平台、版本和一组"功能 ID + 日期"
- [ ] 校验：功能 ID 必须在登记模块里；安装 ID 必须是 UUID；平台必须是已知值（Windows、Android）；日期和服务器当天最多相差 2 天；单次条数有上限
- [ ] 只要有一条不合格，整个请求拒绝，响应里写明是哪一条、什么原因
- [ ] 重复上报同一行直接忽略，累计汇总不重复计数
- [ ] 按连接来源 IP 限流，IP 只在内存里用，不写库、不写日志；沿用现有的可信代理配置
- [ ] 登记模块随在线服务的部署包一起打包，不复制第二份；打包脚本相应调整
- [ ] 测试用现有的 PGlite 夹具，通过 HTTP 覆盖：每类校验拒绝、去重、累计汇总不重复计数、限流
- [ ] 验证：只跑在线服务的新测试文件
