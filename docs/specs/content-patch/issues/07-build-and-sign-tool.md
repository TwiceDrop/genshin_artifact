## Comments

- 2026-11-20：已实现，工具在 `beta-tools/patch-tool.mjs`，两个子命令：
  - 生成密钥对：`node beta-tools/patch-tool.mjs keygen --out <路径前缀>`，得到 `<前缀>.key`（PKCS8 PEM 私钥）和 `<前缀>.pub`，并把公钥的 Base64 打印出来，这个值就是要写进构建配置的客户端公钥。私钥文件用「已存在则失败」的方式创建，不会覆盖旧密钥；打印内容里没有私钥。
  - 打补丁包：把环境变量 `MONA_PATCH_SIGNING_KEY` 设为私钥文件路径，然后 `node beta-tools/patch-tool.mjs build --base-min 7.2.05EA --base-max 7.2.05EA.99 (--patch 7.2.05EA.01 | --previous <上一个补丁的目录或 manifest.json>) --out <输出目录> [--source-root <根目录>] <登记表内的数据路径>...`。
  - 输出：`manifest.json`、`manifest.sig`（64 字节原始签名）、`files/<键>.json`（键是 `PATCHABLE_DATA` 的键，与 `PatchStore` 的存放方式一致）。数据文件会解析后压缩成 JSON 写入，所以文件内容与源文件不是逐字节相同；角色数据 `_gen_character.js` 会去掉 `export default` 外壳。
  - **补丁号**：`--patch` 手动指定，或 `--previous` 取上一个补丁清单里的补丁号，补丁段加一并保持位数（`.09` 到 `.10`，`.99` 到 `.100`）。两者必须二选一，都不给或都给就报错，不会猜一个默认值。`--previous` 只接受清单，不接受随手写的版本号，免得把基础版本 `7.2.05` 误当成补丁号。
  - **拒绝的情况**：不在登记表内的文件（含 `..`）、文件重复、源文件读不到或不是 JSON、基础版本无法识别或 min 大于 max、补丁号无法识别、没有私钥或私钥格式不对、输出目录非空。拒绝时不写任何文件。
  - **自检**：签名后用 `server/patch-package.mjs` 的 `verifyPatchPackage`（与客户端同一个函数）验一遍，用私钥推出的公钥和 `--base-min` 作为当前版本，不通过就不输出。
  - **不接发布**：工具只写本地文件，没有任何网络、git 或 Release 调用。
  - 补丁包在网络上怎么传（逐个文件还是压缩包）还没定，留给任务 05；现在是一个目录。
- 验证：`tests/patch-tool.test.mjs` 9 项，连同 `patch-package`、`patch-store` 共 30 项通过。覆盖：密钥对生成与拒绝覆盖、打出的包从磁盘读回后通过客户端校验、数据转换、用仓库里 5 个真实数据文件打包并验证、补丁号自动加一和位数、非法输入不留文件、非空输出目录、命令行读环境变量和拒绝未知参数。另外在测试目录里真实运行了一遍命令行（keygen、两次 build 含 `--previous`、缺私钥、表外文件），结果符合预期，失败的两次没有生成目录，测试目录已删除。没有用真实发布密钥，也没有生成可发布的补丁。
