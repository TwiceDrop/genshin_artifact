## Comments

- 2026-11-20：已实现。开发者同意按建议定文案和统计方案。
  - **设置页**：`src/pages/SetupPage/SetupPage.vue` 新增一行。左边是「内容补丁」，右边依次是补丁号（没有补丁显示「无」）、「自动获取内容补丁」字样和开关。用了批准的文案，没有加别的字。构建没有配置补丁通道（地址或公钥为空）或在 Android 上，这一行不显示。窄屏上标签不换行，补丁号和开关在剩下的位置里换行。开关写进 `localStorage`，关闭后页面不再向本机服务发检查请求。
  - **补丁状态**：本机服务新增 `GET /api/patch/info?version=…`，返回正在生效的补丁（不含补丁数据，只有补丁号、适用范围、文件和哈希）、待下次启动生效的补丁号和最近一次检查的结果。页面端 `src/platform/patch-info.mjs`：`activePatch` 给设置页显示，`patchDebugInfo()` 给 Debug 导出。`App.vue` 启动时和每次检查完成后刷新。
  - **Debug 导出**：单人配装的调试包在 `environment.contentPatch`，四人轴的导出在顶层 `contentPatch`。内容：是否配置、玩家开关、正在生效的补丁（补丁号、适用范围、各文件和哈希）、被拒绝补丁的阶段和原因、待生效的补丁号、最近一次检查的状态和失败阶段与原因。不含补丁数据本身。
  - **使用统计（客户端）**：上报在有补丁时多带一个 `patch` 字段，`version` 仍是基础版本；没有补丁时上报内容与之前完全相同。读的是这次运行正在生效的补丁号，启动初期读取状态之前上报的批次可能不带。
  - **使用统计（服务端，需要部署）**：新增迁移 `online-service/migrations/010_usage_stats_patch.sql`，给 `usage_stats_days` 加一列 `patch text NOT NULL DEFAULT ''`，不进主键。同一天同一功能只有一行，记下的是第一次存这一行时的补丁号。累计表和按角色的表不加这一列。上报接口接受可选的 `patch`（格式与版本相同，空字符串或非法值返回 400）；统计汇总接口新增 `patch` 筛选和 `patches` 列表，统计页多一个「补丁」下拉。补丁筛选只作用于按天的数字（近 7 天、近 30 天、每日活跃），累计数不受影响。迁移由部署时的迁移步骤自动执行。新客户端对没升级的旧服务端上报也能正常工作（多出的字段被忽略），所以上线顺序没有要求。
  - **顺带修的**：`online-service/tests/usage-stats-summary.test.mjs` 里功能总数写的是 28，而 `4bad0b8` 加了 `page.online-account` 后实际是 29，这个测试从那次提交起就一直是红的（当时没有跑 online-service 的测试），已改成 29。
