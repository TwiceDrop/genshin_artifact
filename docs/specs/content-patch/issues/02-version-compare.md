# 02: 版本比较支持 EA 与补丁号

**What to build:** 让现有版本比较能处理 `7.2.05EA`、`7.2.05EA.01` 这类版本号，并且同号 EA 排在正式版之前。

**Blocked by:** None (can start immediately)

**Status:** done

开发者 2026-11-20 同意：同号 EA 早于正式版，补丁号写在 EA 后面（`7.2.05EA.01`）。

现有实现：`server/update-sources.mjs` 的 `compareVersions`。它的正则只认「数字加可选的 `EA` 或 `-`、`+` 后缀」，`EA` 后面再跟 `.01` 会返回无法判断，同号的 EA 和正式版比较结果为 0。

- [x] 改比较规则：同号时 EA 小于正式版；`EA` 后面可以接补丁段（`7.2.05EA.01`），补丁段大的更新
- [x] 保持现有行为不变：多段数字版本、`v` 前缀、`-`/`+` 后缀、无法识别时返回 null
- [x] 检查调用方：`describeRelease`（`src/platform/release-update.mjs`）、`LocalUpdater`、更新弹窗，确认改规则后版本比较的结果和界面提示一致
- [x] 使用统计服务的版本格式 `VERSION` 允许字母和 `.`，不需要改。只用同一条正则在 Node 里核对了 `7.2.05EA.01`、`7.2.05EA`、`7.2.05.01` 都通过，没有为它新增测试用例
- [x] 测试：EA 与同号正式版的先后、EA 加补丁号的先后、不同基础版本的补丁号比较、原有用例全部保持通过
- [x] 验证：跑 `update-sources` 相关的现有测试加新增用例

## Comments

- 2026-11-20：已实现。排序为 `7.2.04 < 7.2.05EA < 7.2.05EA.01 < 7.2.05EA.02 < 7.2.05 < 7.2.05.01 < 7.2.06EA`；`EA` 和 `-EA` 等价，大小写不敏感，数字段仍按数值比较（前导零不影响）。`EA` 后面的补丁段不是数字时返回无法判断。其他 `-`、`+` 后缀仍不参与比较，行为不变。
- 调用方：`fetchReleaseMetadata`（取最新版本）、`describeRelease`（界面是否提示更新）、`LocalUpdater` 都只用返回值的符号，没有改。装了 `7.2.05EA` 的玩家现在会被提示更新到 `v7.2.05`。
- 验证：`tests/release-update.test.mjs` 新增两项（全排列顺序、EA 到正式版的提示），连同 `cnb-update`、`auto-update-7109` 共 21 项通过。使用统计服务的 `VERSION` 格式没动，只做了正则的一次性核对，没有新增它的测试用例。
