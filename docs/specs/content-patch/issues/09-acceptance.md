**Blocked by:** 03, 04, 05, 06, 07

**Status:** ready-for-human

## Comments

- 2026-11-20：按清单跑了一遍，环境是 `vue-cli-service build` 构建的完整页面（补丁地址、公钥和统计地址都指向本机），本机服务，一个本机静态服务当补丁地址，一个本机服务接收统计上报，内置浏览器驱动。没有用安装包，也没有用真实发布密钥。测试用的 Amber + 柔风游弦（90 级）在计算器页里的面板读数：
  - **补丁让结果变化**：补丁把柔风游弦的副词条加 0.2。没有补丁的那次运行，暴击率 32.6%、期望伤害 294；补丁下载后（本次运行不变）重启本机服务再载入，暴击率 52.6%（正好多 20 个点）、期望伤害 319。设置页显示「7.2.04.01」。
  - **改坏一个字节**：（1）服务器上的补丁被改一个字节，下载时被拒绝，阶段是哈希，已生效的补丁继续用，没有待生效的补丁；（2）已装在本机的补丁被改一个字节，重启后读取被拒绝（哈希），页面用安装包原数据，暴击率回到 32.6%、期望伤害 294，控制台输出「内容补丁未生效，使用安装包原数据」和原因。
  - **损坏的补丁自动修复**：做第（2）项时发现问题，见下面「验收中发现并修的问题」。
  - **版本**：把适用 7.2.03 的旧补丁留在本机，当前版本 7.2.04，读取时被拒绝（阶段是版本），原因里写明适用范围和当前版本，用原数据。这只是不生效，文件还在，和任务原写的「自动作废」不同。
  - **回滚**：`PatchStore.rollback()` 后目录清空，重启后覆盖接口返回没有补丁，设置页补丁一行显示「无」。
  - **离线**：补丁服务停掉，已装的补丁仍然生效，最近一次检查是失败（阶段下载），页面正常，没有弹窗。
  - **使用统计**：同一次实测里收到的两次上报。没有补丁时的那次只有 installId、platform、version、records，和以前一样；补丁生效后的那次多了 `"patch":"7.2.04.01"`，version 仍是 `7.2.04`。
  - **验收中发现并修的问题**：已装的补丁被改坏后，补丁号还是被当作「已安装」，同一个补丁号不会重新下载，除非出了更新的补丁；清单没变化时的 304 也会让它继续不修。已改：`PatchStore.latestPatch()` 不再把文件缺失或哈希不对的补丁算作已安装，更新器只有在记下的补丁仍然完好时才带 ETag；`/api/patch/info` 的待生效补丁号改用新的 `pendingPatch()`，原来在当前补丁被拒绝时会把它误报成待生效。修后在同一套环境里重做：损坏的补丁在该次运行被拒绝并用原数据，同一次检查重新下载并装为待生效，下次启动恢复生效。新增测试 `a damaged installed patch does not count as installed...`，以及信息接口的断言。
  - **没验证的**：（1）Debug 导出没有在浏览器里实际导出。单人配装的调试包要先跑出配装结果，测试库里没有圣遗物，点自动配装只提示没有符合条件的圣遗物；四人轴导出同样需要计算结果。所以导出里的 `contentPatch` 字段只由单元测试和 `/api/patch/info` 的返回值覆盖，两个页面里导出代码的改动没有被运行过。（2）没有用安装包，没有测安装器覆盖升级后补丁的行为。（3）没有真实升级基础版本，用旧范围的补丁模拟。（4）没有用真实密钥和真实补丁地址，没有 HTTPS。（5）统计的服务端列和统计页的补丁下拉没有连真实服务，也没有在浏览器里看过。（6）没有在 Android 上测，第一版不支持。
