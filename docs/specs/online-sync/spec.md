# 在线同步

目的：记下 2026-11-12 与开发者对齐的结论。搭档部署在线服务时，同步接口和使用统计一起上线，不为同步另做一次部署。

## 已定结论

- 这次不改服务端代码，照现有的部署包部署（`online-service/scripts/pack.py`）。账号登录、Cookie 托管拉取、云端档案和历史记录的接口与迁移都已经在包里，`online-service/tests/profiles.test.mjs` 和 `backend.test.mjs` 通过。客户端的在线账号入口继续隐藏，以后发版接入时再做实机验收。
- Cookie 单向托管：服务端加密保存，只用来定时拉取，不会下发给任何设备。其他设备能看到托管账号和拉到的快照，可以导入或手动拉取。
- 冲突处理保持现状：按修订号先到先得，后到的提交保存为冲突副本并提示用户，不自动合并。
- 搭档提的六类同步对应到现有结构，不新增数据类别：

| 同步内容 | 现有对应 |
| --- | --- |
| Cookie | 托管游戏账号（`/v1/game-accounts`） |
| UID | 托管账号的 UID 列表；档案里的 `miyoushe` |
| 圣遗物 | 档案 `artifacts` |
| 角色数据 | 档案 `presets`、`kumi`；托管账号的最新角色快照 |
| 历史记录 | `/v1/profiles/:id/history` |
| 轴文件 | 档案 `teamDpsConfigurations`、`teamDpsTasks` |

## 以后再做

以下两项这次不做，等客户端真要新增数据类别时一起处理，届时服务端重新部署一次。

- **档案校验只查外层。** 现在服务端要求档案顶层字段正好是上面那 8 个，且 `schemaVersion` 等于 1，多一个类别或升级版本号就会拒收。改成只校验操作 ID、设备 ID、修订号、大小和名称，未知类别与更高版本原样保存；客户端读到比自己新的格式时拒绝导入并提示更新。这是放宽校验，动手前要再和开发者确认。
- **接口版本约定。** `/v1` 只做加法：新增接口和可选字段，不删字段、不改含义、不把可选改成必填。不兼容的改动另开 `/v2`，与 `/v1` 并存到旧客户端基本不用为止。定下来后写成 ADR。
