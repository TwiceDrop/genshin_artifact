# 无已保存圣遗物的预设参与四人轴优化

## 需求与原因

开发者要求：没有保存圣遗物的角色预设也要正常参与四人轴优化，只跳过旧配装对比。

预设缺少 `artifactIds` 时，页面生成的 `initial_ids` 对应项为 `undefined`，JSON 快照将其转换为 `null`。优化器构造旧配装时直接对该项调用 `.map()`，导致搜索开始前抛出 `Cannot read properties of null (reading 'map')`。

## 实现

- 共用优化器构造旧配装时，只要任意角色的已保存装备列表为 `null` 或 `undefined`，就返回无旧配装基准（`baseline: null`）。
- 正常搜索、装备分配、限制条件及最终结果详情沿用现有逻辑；四人都有完整装备时继续计算旧配装对比。
- 不改写预设、库存或调试包，不为缺失装备补造旧配装。“计算当前配装”仍要求四人装备完整。

## 验证

- `node --test tests/team-dps-missing-artifacts.test.mjs`：修复前 3 项复现相同异常、2 项完整旧配装用例通过；修复后 5 项全部通过。
- 合成数据覆盖单人缺失、四人全缺失、JSON 的 `null` 和直接调用的 `undefined`；串行和并行优化均与已有的空装备列表行为一致，结果分配 20 件互不重复的圣遗物，输入保持不变。
- 实际 CPU Worker 路径验证缺失装备时仍生成优化结果与事件详情；并行详情回调仅执行最终结果阶段，完整旧配装仍执行基准阶段。
- 使用开发者提供的 Debug 输入回放，保留原始 `null` 装备项，配合合成库存、将搜索限制为 1 组：成功返回 1 组结果、20 件互不重复的圣遗物，`baseline` 为 `null`。原始文件未修改，真实数据不纳入仓库。
- 未执行浏览器实测或客户端打包。
