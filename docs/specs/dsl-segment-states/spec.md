# MONA-DSL 逐段 BUFF、角色与武器效果及独立属性图

Status: ready-for-agent

## 要交付什么

让作者在同一个单人配装目标中，为不同技能段选择外部 BUFF、设置角色和武器效果，并读取该段的属性。计算器固定一套候选圣遗物，算完这套装备在各状态下的表现，再用原有 `result` 表达式给整套装备评分。作者手动声明每段处于什么状态；四人轴的自动触发、计时和扣层留在四人轴引擎。

## 作者如何表达一套手法

以下是本次要新增的源码写法。示例使用玛薇卡已有的 `Q1` 和 `ECharged1` 技能标识。队友参数是示例值。相同技能可以重复声明并绑定不同状态。

```text
buff bennett = BennettQ({ base_atk: 700, skill3: 6, c1: false })
buff xilonen = XilonenE({ elements: ["Pyro"], skill_level: 8 })

state burst = { buffs: [bennett, xilonen] }
state ride  = { buffs: [xilonen] }
state tail  = { buffs: [] }

dmg opening = Mavuika.Q1        @burst
dmg spin    = Mavuika.ECharged1 @ride
dmg last    = Mavuika.ECharged1 @tail
prop openingAtk = Mavuika.atk   @burst

result = opening.normal.e + spin.normal.e * 2 + last.normal.e
```

| 构造 | 实现约定 |
| --- | --- |
| `buff 别名 = 规则名({ 参数 })` | 规则名使用现有 BUFF 标识，参数按对应规则的数据契约保存。生成器将选中条目的实际配置写入源码。别名只在本脚本内有效，同名规则的两种配置可分别起名。 |
| `state 名称 = { buffs: [...] }` | 每个命名状态显式列出这一段完整的外部 BUFF，顺序按列表保留。`[]` 表示无外部 BUFF。基础角色、武器、圣遗物套装及敌人设置仍然生效。 |
| `character`、`weapon` | 状态内可选的两个对象，例如 `state tail = { buffs: [], weapon: { … } }`（省略号代表所选武器真实的效果字段）。每个对象按字段覆盖基础配置，使用当前角色、当前武器已有的参数名和类型。省略字段沿用基础值；显式的 `0` 和 `false` 要保留。 |
| `dmg … @状态`、`prop … @状态` | 状态标记放在声明末尾，技能自身参数及附魔保留原位置。未标状态的声明沿用本次计算的完整基础配置，包括当前启用的外部 BUFF。状态之间互不继承。 |
| `result` | 保留原有表达式能力，包括次数、权重、条件、比较和属性读取。示例中前两次重击共用状态，最后一次重击单独结算。 |

整份源码应包含还原命名 BUFF 和状态所需的数据。复制、导入和预设保存都传递同一份源码。队友的手填来源面板随配置保存；受益角色和候选装备始终取本次计算输入。接收方可以用自己的库存优化同一套手法。

## 计算如何接入

1. **准备目标函数**。每次优化先解析一次源码，解析出 BUFF 别名、状态、带状态的伤害与属性声明，以及最终表达式。传统 DSL 沿用已有入口。带状态的脚本也应保留已适配的角色、技能和反应语义；参数、状态引用等错误通过现有错误通道指明阶段、声明位置和原因。
2. **按候选和状态构建计算输入**。先确定当前候选的五件圣遗物，再从同一基础角色、武器和敌人设置派生各状态。按状态覆盖角色与武器效果、选择外部 BUFF，经过已有的配置转换、属性图与伤害规则。班尼特的固定攻击取来源角色的配置，希诺宁的减抗作用于所选元素的敌方抗性。两者都需随段切换。已有的作用域、同源叠加与停用语义见[公式与属性作用域](../../dev/formula-scope.md)。
3. **求整套候选的分数**。在同一候选内，同一状态的各次 `dmg` 和 `prop` 可以共享属性图和敌方状态；技能参数、附魔和反应仍按各自声明求值。换候选、修改词条或切换基础输入时，重新求依赖它们的值。把所有声明的结果送回原表达式，一次求出该候选的 `result`。
4. **接入实际搜索**。先以小库存穷举打通每套候选的完整评分，再接入现有搜索和返回结果的复算。A* 等加速路径使用的上界必须覆盖完整目标，包括跨状态的条件表达式；只有能保证正确排序的剪枝才可用于这类目标。仅对传统目标的前几名复算可能直接漏掉最优解。

浏览器与 Node 从[内核组合入口](../../../beta-data/compose-kernel-api.mjs)接入同一份实现。保持原始发布 WASM，沿用现有角色和装备适配。现有 [Rust DSL 目标函数](../../../mona_wasm/src/target_function/dsl_tf.rs)展示了每次求值接收一张属性图的接口形状；[单人配装 Worker](../../../src/workers/single-optimize-handler.mjs)把整次搜索交给优化器。优先验证运行时能够在候选评分的位置调用多状态目标函数，再定扩展内核和 JS 适配层的具体分工。

## 实施顺序

| 顺序 | 交付结果 |
| --- | --- |
| 1 | 用手写 DSL 跑通两状态、两候选的单套求值和实际搜索。保留每段值和整套总分作对照，确认最优套装来自完整搜索。 |
| 2 | 接齐角色与武器效果覆盖、状态属性读取、结果复算、词条收益和动态评分。沿用既有公式，在各入口复用同一个多状态目标。 |
| 3 | 在现有 [DSL 生成器](../../../src/algorithms/dsl-generator.mjs) 中增加命名状态编辑与逐段选择。能从现有配置选择 BUFF、填写各状态的效果参数，生成与手写等价的源码。按项目约定先确认面向玩家的新增提示文案。 |

## 验收

| 用例 | 通过条件 |
| --- | --- |
| 旧 DSL 与混合声明 | 同一旧脚本在相同输入下总分和排序一致。新脚本里未标状态的 `dmg`、`prop` 与原有基础设置单算一致。 |
| 三段外部 BUFF | 固定一套合成装备，对“双 BUFF、仅希诺宁、无外部 BUFF”分别手动单算，再和脚本逐段比。独立核对班尼特带来的攻击差、希诺宁带来的火抗差，并核对 `openingAtk`。 |
| 角色与武器状态隔离 | 选有真实可配置效果的角色和武器，分别改变角色条件、武器层数，再组合两者。显式零层和关闭状态生效；交换声明顺序后，各段仍与独立预期相符。 |
| 候选排序与重算 | 构造两段各计一次的评分夹具，甲套两段为 100、40，乙套为 80、80。应返回乙套 160，甲套 140。用小库存比较实际搜索与穷举的结果，并核对配装结果页的复算值。 |
| 源码往返与其他入口 | 生成器输出经复制、导入和预设重载后，保留状态定义、参数和总分。在同一合成输入上，词条收益等于改变词条前后的完整目标差值，动态评分使用对应的多状态目标值。 |
