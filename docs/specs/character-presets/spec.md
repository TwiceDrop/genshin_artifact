# 角色预设分类、编辑与应用配装结果

Status: done

Q1–Q17 已全部确认，包括旧字段初始值、界面文案及验收安排；实现与验证已完成。

## Problem Statement

UID 导入的角色和玩家自行保存的配装混在同一份预设列表中，刷新行为、计算时装备占用与保存结果的含义不够清晰。玩家需要分别管理随游戏更新的预设和独立维护的预设，并能从计算结果直接更新某一份配装。

## Solution

角色预设页分为「游戏内」「自定义」两个标签，计算器导入预设时使用有相同标签和搜索的二级菜单。配装的「替换圣遗物」增加两个来源子选项；结果圣遗物下面提供「应用圣遗物到预设」，可以只替换同角色已有预设的圣遗物，也可以按当前状态新建自定义预设。桌面端和新移动端同步提供这些功能。

### 已确认：来源分类与刷新

- 旧预设带 UID 导入来源标记的归入游戏内，不带标记的归入自定义。分类时保留名称、圣遗物及全部现有配置，不按名称或装备相似程度猜来源。
- 旧游戏内预设可能已手动修改过，仍按其来源分类；等下一次成功刷新时才更新游戏数据。
- 每个 UID 的每个角色有一份游戏内预设，继续使用既有的角色身份区分方式。刷新只影响对应 UID。
- 刷新更新角色等级、突破、命座、天赋、武器养成和已装备圣遗物。
- 保留手动计算设置：额外 BUFF、角色机制条件、同一武器的触发参数、套装触发与模式、队友来源与触发、计算目标、DSL、约束及筛选等。更换武器时，不沿用旧武器的触发参数。
- 未返回或同步失败的角色保留上次数据，沿用现有错误与警告信息。
- 游戏内预设允许手动修改，也允许应用计算结果；之后刷新会覆盖其手动修改的游戏数据，仍保留上述手动计算设置。
- 自定义预设不随普通 UID 刷新改变。同角色可保存多个不同名称的自定义预设。
- 联网刷新与原始角色快照导入采用同一刷新规则；UID 数据包导入继续用于完整恢复包内数据，包括包内 BUFF，不改成本地 BUFF 优先。

### 已确认：装备占用与应用结果

- 游戏内来源的装备占用以最近同步的游戏内穿戴记录为依据，不使用手动修改后的游戏内预设装备作为游戏穿戴记录。
- 自定义来源的装备占用以自定义预设保存的装备为依据。
- 「应用圣遗物到预设」使用结果区当前显示的五件圣遗物，包含计算后手动调整的选择。
- 覆盖已有预设时只换圣遗物，保留目标预设的角色、武器、BUFF、名称和来源等其他内容。
- 新建时使用点击当时的角色、武器、BUFF 和计算设置，始终新建为自定义预设。
- 应用结果的目标限定为当前角色已有的预设。
- 两个替换子选项的勾选表示允许使用对应类别中其他角色占用的圣遗物。总开关关闭时两类都保护；开启时两个子项初始都勾选，之后保留各自选择。保留升级前总开关的开关状态。
- 同角色的全部自定义预设视为当前角色自己的装备，不因自定义来源保护而排除。游戏内仍按当前 UID 的当前角色穿戴记录豁免。
- 一件圣遗物只要仍被任一受保护的其他角色占用，就从候选中排除；允许某个来源不抵消另一个来源的保护。
- 手动锁定、选中的队友预设占用、圣遗物组筛选和现有主词条等限制继续优先，不被新增勾选或同角色豁免绕过。
- 只允许将完整五件、在当前仓库中仍存在且内容与显示一致的圣遗物应用到预设。历史快照缺失或内容已变更时阻止操作并明确提示，不重建仓库装备。
- 新建及保存预设补齐当前展示技能及其参数、敌人设置、附魔、当前五件圣遗物的套装触发条件；导入时恢复这些状态。

### 已确认：列表、导入与应用菜单

- 预设页、导入菜单、应用结果菜单均提供「游戏内」「自定义」标签。
- 游戏内标签默认显示当前选中 UID，提供 UID 切换；自定义标签显示当前莫娜账号全部自定义预设。
- 搜索匹配角色名与预设名；应用结果菜单的搜索始终限定为当前角色。
- 导入角色预设通过二级菜单选择。两端保持同一分类、搜索和选择规则，使用各自既有弹层呈现。
- 应用已有预设时，选择目标即执行仅替换圣遗物的动作；新建走名称输入与保存流程。

### 已确认：预设编辑

- 在预设页通过编辑弹窗创建或编辑预设，不再必须跳到计算器完成编辑。
- 自定义预设支持选择角色并编辑等级、命座、天赋、武器、圣遗物和 BUFF。
- 两端使用同一套编辑行为和数据规则。
- 游戏内预设不能换成另一名角色，可以将当前配置另存为自定义。自定义预设可选择角色。
- 新建时名称必须与当前莫娜账号中的已有预设不同，重名要求改名；只有明确选择已有预设才允许覆盖。

## User Stories

1. 作为玩家，我希望区分游戏内和自定义预设，以便知道哪些配置会随 UID 刷新改变。
2. 作为已有用户，我希望旧预设按明确的来源分类，且分类不改动保存内容。
3. 作为玩家，我希望导入 UID 后自动生成游戏内预设，无需逐个保存角色。
4. 作为玩家，我希望刷新更新游戏养成与装备，同时保留我设置的 BUFF 和计算条件。
5. 作为持有多个 UID 的玩家，我希望刷新某个 UID 不改动其他 UID 的预设。
6. 作为玩家，我希望一次同步缺少角色时仍保留上次可用配置，并看到真实同步问题。
7. 作为玩家，我希望临时修改游戏内预设以尝试配装，并在下一次刷新时重新获取游戏数据。
8. 作为玩家，我希望同一个角色可以保存多个独立的自定义预设，不受普通 UID 刷新影响。
9. 作为玩家，我希望在预设页直接选择角色、编辑养成和配装并保存。
10. 作为玩家，我希望从计算器导入预设时可以切换分类并搜索，快速找到目标配置。
11. 作为玩家，我希望分别控制是否使用其他游戏角色和自定义预设占用的圣遗物。
12. 作为玩家，我希望游戏内装备占用仍反映最近同步的实际穿戴，不因试改预设而改变。
13. 作为玩家，我希望将当前显示的计算配装应用到同角色已有预设，只替换圣遗物。
14. 作为玩家，我希望以当前配置新建自定义预设，以便保留这次配装。
15. 作为跨设备用户，我希望 UID 数据包仍能完整恢复保存的数据。
16. 作为移动端用户，我希望获得与桌面端一致的分类、编辑、导入与结果应用能力。
17. 作为玩家，我希望同角色的多个自定义方案不会互相阻碍搜索，同时仍尊重其他角色对共享装备的保护。
18. 作为玩家，我希望替换选项不会绕过我手动锁定、队友占用和圣遗物组筛选。
19. 作为多 UID 用户，我希望在游戏内标签切换 UID，并确认要导入或覆盖的是哪个 UID 的角色。
20. 作为玩家，我希望缺失或已变化的历史装备不能被静默保存成另一套装备。
21. 作为玩家，我希望重新导入新保存的预设后，敌人、附魔、展示技能和当前套装触发条件也被恢复。
22. 作为玩家，我希望新建重名预设时得到明确提示，不意外覆盖另一份配置。
23. 作为玩家，我希望把游戏内角色的配置另存为自定义，形成独立保存的配装。

## Implementation Decisions

- 沿用现有按莫娜账号保存预设、按 UID 保存游戏穿戴记录的边界，不更换存储位置或存储键。
- 分类依据现有 UID 来源元数据；预设的可编辑装备与游戏内穿戴记录保持分别维护。
- 共用预设分类、筛选和操作入口，桌面与新移动端呈现相同规则。
- 不修改伤害公式、计算内核或原始发布内核。
- 现有名称仍作为预设标识，不增加重命名功能；编辑保存原名称，另存为使用新名称。现有队友、UID 来源和四人轴对预设的引用保持有效。
- 使用既有的角色、武器、圣遗物、BUFF 和计算设置编辑控件；角色预设弹窗拥有独立编辑状态，取消时不写入预设或计算器当前状态。
- 保存与导入的预设状态在公共模块维护，结果应用和预设弹窗调用相同操作，避免各自复制状态字段或分类规则。
- 新增四项页面状态按预设保存。恢复套装触发条件时先建立完整既有初始配置再应用保存值，避免套装条件从上一个预设残留。
- 新建重名与结果装备完整性/一致性检查集中在保存操作入口，使用用户已确认的拒绝规则，内部模块不重复校验。
- 当前五件完整性限制仅针对「应用圣遗物到预设」；普通预设编辑沿用现有可保存不完整配装的范围。

### 已确认：旧预设缺少新增状态时

旧数据没有保存这四项，无法恢复历史上未记录的值。按字段使用既有新建计算的初始值，不从导入前页面继承；已有字段原样恢复：

| 缺少的状态 | 使用的既有初始设置 |
| --- | --- |
| 敌人 | 90 级，七元素与物理抗性均为 10% |
| 附魔 | 无附魔 |
| 当前展示技能及参数 | 对应角色技能下拉的第一个技能，以及角色元数据声明的技能参数初始值 |
| 当前五件套装触发条件 | 各套装元数据声明的二件套、四件套初始配置，不统一假定为关闭或零层 |

此规则用于旧预设，以及 UID 首次生成但尚未保存这些手动设置的预设。后续 UID 刷新保留这些已保存的手动设置。

### 已确认：新增界面文案

既有角色、武器、BUFF 等编辑控件沿用原文案；新增入口与提示使用下表，不额外加入说明性小字或免责声明。

| 位置 | 文案 |
| --- | --- |
| 分类标签 | 游戏内 / 自定义 |
| UID 选择 | UID |
| 搜索输入 | 搜索角色或预设名称 |
| 新建入口 | 新建自定义预设 |
| 编辑窗口 | 编辑角色预设 |
| 名称输入 | 预设名称 |
| 游戏内另存入口 | 另存为自定义 |
| 计算器导入入口 | 导入角色预设 |
| 替换子选项 | 包含游戏内角色 / 包含自定义角色 |
| 结果应用入口 | 应用圣遗物到预设 |
| 新建重名提示 | 已有同名预设，请使用其他名称。 |
| 名称为空提示 | 请输入预设名称。 |
| 应用结果不足五件 | 当前配装不足五件，无法应用到预设。 |
| 应用结果装备缺失或改变 | 圣遗物已从仓库移除或发生变化，请重新选择后再应用。 |
| 空列表或搜索无匹配 | 暂无符合条件的预设 |
| 应用成功 | 已应用圣遗物到预设。 |

保存、取消、角色选择等通用操作沿用已有文案。预设页不新增删除 UID、改名或改变导入文件覆盖语义等功能。

## Testing Decisions

只使用合成数据，不访问真实账号或存档；测试从实际保存/导入操作与配装候选入口验证外部行为，不镜像实现细节。

每轮最多五项有明确目的的验证：

1. 预设工作流针对性测试：旧来源分类不改内容；UID 刷新保留手动设置且不影响自定义/其他 UID；新保存状态往返一致；覆盖仅换圣遗物；拒绝重名和无法复现的装备。
2. 配装候选筛选针对性测试：总开关及两个子项的组合、同角色豁免、共享装备保护、真实游戏穿戴与可编辑预设分离，并核对已有锁定、队友和圣遗物组约束。
3. 桌面构建，核对共用逻辑与桌面组件编译。
4. 新移动 UI 构建，核对移动替换组件编译。
5. 隔离的合成数据浏览器验收，两端分别走预设新建/编辑、分类搜索导入、应用当前结果和刷新规则；不读取或清理开发者现有浏览器数据。

现有预设导入、游戏装备归属、来源分组筛选与移动控件测试提供测试模式参考。不运行全量测试；若环境限制导致浏览器验收无法完成，报告实际覆盖与未验证范围，不宣称实测通过。文档对齐阶段不构建、不运行功能测试。

## Out of Scope

- 发布、推送、创建远端 PR、改 README。
- 游戏服务器上的实际换装；「应用」只修改本地预设。
- 伤害公式、角色倍率、计算内核改动。
- 把 UID 数据包恢复改成普通 UID 刷新语义。
- 预设重命名及名称引用迁移。
- 自动恢复或重新创建已被删除的历史圣遗物。
- 与本次新增字段无关的旧预设残缺字段兼容问题。

### 实现与验证结果

- 分类直接使用既有 UID 来源标记，不改写旧预设的名称、装备和配置。预设页、计算器导入及结果应用共用分类与搜索组件。
- 保存、刷新、结果应用共用预设操作；角色和武器表单恢复、队友 BUFF 编辑以及约束序列化抽到共用入口，消除预设页与计算器之间的重复。
- 两类替换权限分别持久化，保护集合综合真实游戏穿戴与其他角色的自定义预设；已有锁定、队友及圣遗物组过滤继续生效。
- 新建预设补齐既有初始计算约束和筛选；保存与恢复新增四项面板状态；同名新建与不完整/不一致装备按已确认规则拒绝。

### 已记录的既有问题（本次范围外）

历史预设若缺少圣遗物选择、BUFF、约束或主词条筛选字段，原有计算器导入逻辑只更新存在的字段，可能沿用导入前页面的相应状态。本次不扩大旧残缺字段兼容范围；新的预设编辑器使用既有初始设置补齐新建配置，避免继续产生缺少约束与筛选的新预设。
