# 登录页

Status: done

2026-11-17 与开发者对齐。同伴正在做账号系统，约定流程为：进入软件先到登录页，可以「以离线模式继续」（即游客，跳过登录），之后进入欢迎页。

## 流程

1. 打开软件后的第一次跳转先过登录门（`src/platform/login-gate.mjs`，接在 `src/router/router.js` 的路由守卫上）：
   - 选过「以离线模式继续」：直接进入。选择记在本机 `localStorage` 的 `mona.offlineMode`。
   - 否则向本机服务读在线账号配置（`cloudApi('config')`），已登录就进入，未登录到登录页。
   - 读取失败（例如开发环境或浏览器里没有本机服务）也到登录页，失败原因显示在登录卡片上。
   - 分享链接导入（`/import`）不拦。
2. 登录页登录成功或选择离线后，回到原来要去的页面（`redirect` 参数），默认欢迎页。登录成功时清除离线选择。
3. 选过离线后想登录：账号页右上「登录在线账号」进入登录页；已登录时登录页直接返回。

## 界面

- 整屏，不显示侧栏、顶栏、底部导航和页脚（路由 `meta.bare`）。
- 背景沿用欢迎页的星空和星盘；星空配色从欢迎页抽到 `src/styles/welcome-palette.css` 的 `.wl-palette`，两页共用。
- 居中卡片：莫娜头像、店名、邮箱、验证码与「发送验证码」、「注册／登录」；卡片下方「以离线模式继续」。

## 接口

沿用在线服务的邮箱验证码登录（与在线账号页相同）：`v1/auth/email/request`、`v1/auth/email/verify`。设备名称自动填 Windows / Android；服务地址不在登录页填写。

## 待同伴处理

- 在线服务目前没有默认地址，本机服务未设置时返回「请先设置服务地址」。账号系统上线前，登录会显示这个错误，只能用离线模式。
- 同伴的账号系统改了接口或流程时，登录页的 `requestCode` / `verifyCode` 和登录门的 `needsLogin` 要一起改。

## 文案

沿用：「邮箱」「验证码」「发送验证码」「N 秒后重发」「注册／登录」；「以离线模式继续」由同伴给出。新增：账号页「登录在线账号」，2026-11-17 开发者已确认。
