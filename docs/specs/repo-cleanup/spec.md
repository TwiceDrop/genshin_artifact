## 给执行者

- 开始前读根目录 `AGENTS.md`，它的规则优先于本规格。
- 一个任务一次本地提交，提交信息说明做了哪个任务。不推送、不建 PR、不改 README。
- 任务完成时，在同一次提交里把任务文件的 `Status:` 改成 `done`，并勾掉验收清单。
- 只做任务文件写明的范围。发现清单之外的问题，记在任务文件末尾的 `## Comments` 下，不顺手处理。
- 遇到下面任一情况就停下来问开发者，不自行决定：搜到了任务说「零引用」的文件的引用；验证失败且原因不在本次改动里；需要新增校验、兜底或默认值；需要改界面文案；任务文件里标着「仍需开发者决定」的部分。
- 每个任务的验证不超过五项，按任务文件列的来。汇报时写清实际跑了什么、结果是什么，没跑的照实说没跑。
- 排查用的数字（文件数、引用数）取自 2026-11-11 的 `cleanup-and-ai-rules` 分支，执行时以当时的搜索结果为准。

## Problem Statement

上一轮清理删掉了重复图片和明显废弃的目录，但仓库里还留着三类问题，让开发者和 agent 都难以判断「哪些是现行的、哪些是历史」：

- 有确定的错误：一条乱码的报错信息、指向已不存在文件的引用、被忽略规则盖住却已提交的内核入口。
- 有上游和历史版本的残留：没人引用的代码与依赖、随发布包分发出去的无关文件、几十个带版本号的脚本、数据和文档。
- 有结构上的负担：两份靠人工同步的包装链、名字与内容不符的目录、写进应用标识的版本号、没有接进构建流程的 Tauri 封装。

## Solution

按风险从低到高分批清理：先修确定的错误，再删零引用的残留，再归档历史文档和脚本，最后处理需要设计决定的结构问题。每批单独提交，能单独验证，也能单独回退。清理后，仓库里留下的每个文件都能回答「谁在用它」。

## User Stories

1. 作为开发者，我希望内核加载失败时看到可读的中文报错，这样玩家反馈的截图能直接定位问题。
2. 作为开发者，我希望在内核入口目录新增文件时 git 能看见它，这样不会漏提交。
3. 作为开发者，我希望源码和许可文件里引用的路径都真实存在，这样顺着引用能找到依据。
4. 作为开发者，我希望发布包里只有软件需要的文件，这样不会把上游的爬虫脚本和备用模板分发给玩家。
5. 作为开发者，我希望 `package.json` 里的依赖都有人在用，这样安装更快、审计范围更小。
6. 作为 agent，我希望 `beta-tools/` 里只剩现行入口和仍在产出证据的脚本，这样不用逐个判断哪个脚本还有效。
7. 作为 agent，我希望 `docs/` 顶层只有现行文档，历史交接和核对记录集中在一处，这样检索时不会把旧结论当成现状。
8. 作为新加入的协作者，我希望刚克隆的仓库里测试的失败都是真失败，这样能分清环境问题和代码问题。
9. 作为开发者，我希望包装链只写一次，这样改注册顺序时不需要记住两处同改。
10. 作为开发者，我希望现行入口的文件名不带过去的版本号，这样不用在规则里额外解释「名字含 7106，仍是当前入口」。
11. 作为开发者，我希望 Tauri 封装的应用标识不随版本变化，这样它以后正式发行时玩家存档不会因为升级而读不到。
12. 作为玩家，我希望升级后存档还在，这样任何涉及端口、应用标识的清理都不能改变现有发行形态的存储位置。

## Implementation Decisions

- 分批提交，一批只做一类事；删除类提交不夹带行为改动。
- 判断「没人用」的依据是全仓引用搜索加一次桌面网页构建，不只看文件名搜索。上一轮已经出现过脚本名零引用、但它产出的证据文件被测试读取的情况，所以删脚本前要同时查它写出的文件有没有被读。
- 归档历史文档用移动而不是删除；被测试、脚本或 README 引用的文档留在原位，或在同一次提交里一起改引用。
- 发布说明 `docs/release-<版本>-final.md` 的位置不动，打包脚本和 README 都按这个路径取文件。
- 现有发行形态的端口、主机名、应用 ID、签名不变。
- 原始发布内核不动（ADR 0001）。
- 包装链收拢成一个由两处入口共同调用的组合模块，入口只负责各自的加载方式（浏览器用 fetch，Node 读文件）。
- 重命名带版本号的现行入口属于波及面很大的机械改动，按「先加新名、分批迁移、最后删旧名」做。只改 Node 入口；已有的带版本号的测试和适配层模块不改名，`beta-data`、`beta-tools` 目录不改名。
- 本项目只做本地发行，上游线上站点专用的构建开关和文档书全部删除。前端调用上游在线接口的三处入口涉及界面，仍由开发者决定。
- 依赖本机既有文件的测试分到单独目录，发版前跑；不提交证据文件，不加自动跳过。
- Tauri 2 封装保留为实验形态，应用标识固定，不采用 PyTauri（ADR 0002）。

## Testing Decisions

- 清理不改变计算结果，所以不新增功能测试；验证方式是确认现有行为没变。
- 每批按 `AGENTS.md` 的上限挑选针对性验证：删前端代码或依赖后跑一次 `npm run build:local`；动入口或包装链后跑走公共入口的现有测试（例如接口核对、配装回归各取一份）。
- 包装链收拢后，补一条测试证明浏览器入口和 Node 入口用的是同一个组合模块，这是唯一新增的测试。
- 文档和忽略规则的改动不跑功能测试，用 `git status`、`git check-ignore` 和引用搜索核对。

## Out of Scope

- 升级 Vue CLI、TypeScript、ESLint、axios 等依赖的主版本。
- 改写 git 历史来缩小克隆体积。
- 修改 README。
- 在线账号服务的部署，以及它的代码清理。
- 删减或修改 vendored skill。
- 把本机服务从 Node 改写成其他语言。
