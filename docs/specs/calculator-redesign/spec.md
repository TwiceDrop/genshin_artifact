# 计算器页重做

Status: ready-for-agent

2026-11-15 与开发者对齐：布局选「角色卡为主」，「开始计算」改名「自动配装」并把配装目标放到明处，颜色默认深色。样稿（静态 HTML，安柏 + 冬极白星默认数据）开发者已认可。任务拆在 `issues/`，按编号顺序做，依赖写在各任务开头。

动手前先读根目录 `AGENTS.md`，它的规则优先于本规格。整体视觉风格（夜空深蓝、金色、龙藏体店名）沿用欢迎页和外框，见分支 `ui-redesign` 上已有的提交。

## 给执行者

- 在本地分支 `ui-redesign` 上做，一个任务一次本地提交，不推送。
- 计算逻辑一概不动：伤害、面板、配装、评分、预设、历史记录的结果必须和改版前一致。
- 页面脚本（`NewArtifactPlanPage.vue` 的 `<script setup>`）里的状态和函数原样保留，新组件通过 props / v-model / 事件接到它们上面。原因：`tests/buff-dialog-7110.test.mjs`、`tests/filter-kumi-7110.test.mjs`、`tests/filter-kumi-source-7204.test.mjs` 直接从页面脚本里取 `handleSelectBuff`、`filterKumiTreeData` 等函数做断言，逻辑搬走会让这些测试失效，也容易悄悄改变数值。
- 新增或改动的界面文字以本规格「文案」一节为准；不在清单里的新文字先问开发者。
- 每轮验证不超过五项，汇报时写清在浏览器里实际点过什么。

## Problem Statement

计算器页是玩家最常用的页面，但现在：

- 伤害结果在第三张卡片中间，要往下滚才看得到。
- 伤害是随改随算的，右上角却还有一个「开始计算」，它实际做的是圣遗物自动配装，名字让人误会。
- 决定配装方向的目标函数藏在右上角的浮层里，平时看不到当前选的是什么。
- 圣遗物区挤着七八个小按钮，武器说明的长段文字和一长串 0.0% 的属性占掉大片空间。
- 编辑模式和配装结果的审阅模式是两套界面，来回切换容易迷路。
- 模板、样式和逻辑都在一个约 2600 行的文件里，约 17 个弹窗。

## Solution

改成「角色卡为主」的单页：

1. **顶部条**（吸顶）：标题「单次计算」、预设按钮、配装目标按钮（显示当前目标名）、账号导入、我的角色、金色主按钮「自动配装」。
2. **角色卡**（夜空色，浅色和深色模式下都一样）：左边角色立绘；中间是元素图标和名字、等级 / 命座 / 天赋三颗胶囊、武器条、五个圣遗物槽位和总评分；右边八项关键面板，底部「全部属性 · 收益曲线」入口。
3. **伤害卡**：左边按普攻、重击、战技、爆发分组的技能列表（取代下拉框），右边大字期望伤害，下面暴击、不暴击；有反应时列出各反应行；有对比基线时显示「之前 → 现在」和差值。技能设置、剧变反应伤害、伤害明细放在下方。
4. **计算条件卡**：BUFF、队友、敌人三行摘要，点开在抽屉里改。
5. **抽屉**：点角色卡或条件卡上的任一块，从右侧滑出对应的编辑抽屉；改动即时生效，旁边的结果跟着变。手机上抽屉从底部升起，占满高度。
6. **自动配装**：点「自动配装」运行配装；配装目标和计算条件、圣遗物筛选都放进「配装设置」抽屉。配装结果直接显示在角色卡上（见实现决定 7），不再有单独的审阅模式。
7. **默认深色**：没在设置里选过外观的玩家，打开就是深色。

## User Stories

1. 作为玩家，我打开计算器第一屏就能看到当前角色、装备和伤害数字。
2. 作为玩家，我点角色卡上的命座胶囊，就能在抽屉里改命座，伤害立即刷新，不用离开当前视图。
3. 作为玩家，我在技能列表里点不同技能，就能看到对应的伤害，不用打开下拉框。
4. 作为玩家，我在顶部条上就能看到当前配装目标是什么。
5. 作为玩家，我点「自动配装」就知道它会帮我挑圣遗物，而不是普通的伤害计算。
6. 作为玩家，配装完成后我在角色卡上就能逐套翻看候选，并看到和原来装备相比伤害涨了多少。
7. 作为玩家，我能一键回到配装前穿的那套圣遗物。
8. 作为玩家，我在手机上也能完成全部操作，抽屉不会被底部导航挡住。
9. 作为第一次打开的玩家，界面默认是深色的。
10. 作为在设置里选过浅色或跟随系统的老玩家，我的选择保持不变。

## Implementation Decisions

### 1. 组件划分

页面脚本保留全部状态和函数；模板按区块拆成同目录下的组件（名字写它是什么，不带版本号）：

| 组件 | 内容 |
| --- | --- |
| `CalcTopBar.vue` | 顶部条 |
| `CharacterHeroCard.vue` | 角色卡 |
| `DamageResultCard.vue` | 伤害卡（复用 `DamagePanel` 的取数和对比逻辑，只换展示） |
| `CalcConditionsCard.vue` | 计算条件卡 |
| `CalcDrawer.vue` | 抽屉外壳：桌面右侧、手机底部，标题、关闭、Esc、焦点管理 |

各抽屉（角色、武器、圣遗物、全部属性、BUFF、队友、敌人、配装设置）的内容留在页面模板里，外面套 `CalcDrawer`。它们绑着页面上四十多个状态，拆成组件要来回传一大串 v-model，只增加接线、不减少耦合（2026-11-15 实现 02、03 时改定）。

现有的子组件（`select-character`、`attribute-panel`、`selected-buff-groups`、`item-config`、`enemy-config-component`、`artifact-config`、`select-target-function`、`dsl-generator`、`panel-search-config` 等）直接放进抽屉里用，不重写。

### 2. 现有区块去向

| 现在 | 改版后 |
| --- | --- |
| 「角色与武器」卡片 | 角色卡上的名字、胶囊、武器条；编辑进「角色」「武器」抽屉 |
| 武器效果长说明 | 武器条只显示一句（取效果第一句），全文在「武器」抽屉 |
| 「圣遗物」卡片（槽位、词条分析、存为套装、应用套装、清空、锁定、评分模式、圣遗物对比） | 角色卡五个槽位 + 总评分；其余按钮进「圣遗物」抽屉 |
| 「伤害计算」卡片 | 伤害卡；「敌人设置」按钮移到条件卡 |
| 「BUFF」卡片 | 条件卡的 BUFF、队友两行，编辑进「BUFF」「队友」抽屉 |
| 右侧属性面板 | 角色卡右侧八项；完整面板和两条收益曲线进「全部属性」抽屉 |
| 目标函数浮层 | 「配装设置」抽屉；顶部条的配装目标按钮打开它 |
| 「计算设置」「圣遗物设置」弹窗 | 先保持弹窗，从「配装设置」抽屉打开 |
| 选圣遗物、伤害明细、添加 BUFF、套装统计、收益曲线、存为/选择圣遗物组、导入角色、米游社选角色、配装进度、比较候选、单件评分 | 保持弹窗不变，只换入口位置 |
| 编辑 / 审阅两种模式与 `SingleResultWorkbench` | 合并成一种；审阅里的结果对比由角色卡和伤害卡承担，见决定 7 |
| 手机上的「角色 / 装备 / 面板」三个标签 | 去掉，整页单列滚动 |

### 3. 角色卡关键面板

固定八项：生命值、攻击力、防御力、元素精通、暴击率、暴击伤害、元素充能效率、角色本元素伤害加成（物理角色用物理伤害加成）。暴击率和暴击伤害用金色强调。有对比基线时每项显示变化方向。

### 4. 角色立绘

优先用米游社的透明底立绘：由角色数据里的头像地址 `.../character_icon/UI_AvatarIcon_<Name>.png?...` 推出 `.../character_image/UI_AvatarIcon_<Name>@2x.png`。头像地址不是这种形式的角色（项目自带图的新角色），改用角色数据里的 `splash`。这是按地址规律推导，不是校验，推导失败或图片加载失败时，立绘位置显示角色头像，不报错也不隐藏角色卡。

### 5. 颜色

- 计算器内容区自带浅色、深色两套变量；角色卡始终是夜空色。
- 变量名避开 `script/postcss-mona-colors.cjs` 识别的角色词（background、text、line、edge、accent、color 等），否则深色模式下会被再映射一次。外框用 `--sh-*`，欢迎页用 `--wl-*`，计算器用 `--cx-*`。
- 默认外观：`src/styles/color-mode.mjs` 里没存过选择时由「跟随系统」改为「深色」。已存的 `mona_color_mode` 不动；设置页的选项不变。

### 6. 自动配装

- 主按钮文字「自动配装」，行为仍是 `handleOptimizeArtifact`。
- 顶部条的配装目标按钮显示当前目标函数名（DSL 时显示「自定义 DSL」，面板配装时显示「面板配装」），点开「配装设置」抽屉。抽屉内容按现在浮层的顺序：伤害 / 面板模式、目标函数（普通 / MONA-DSL / DSL 生成器）、结果条数、Debug、允许替换他人已穿戴、「计算设置」「圣遗物设置」两个入口。

### 7. 配装结果

- 去掉 `editorOpen` 双模式，页面始终是同一套视图。
- 有配装结果时，角色卡顶部出现结果条：「配装结果 第 n / N 套」、上一套 / 下一套、「对比候选」（打开现有的比较候选弹窗）、「恢复原装备」（回到配装前的五件）。
- 角色卡的面板、伤害卡的数字显示和配装前相比的变化（沿用 `comparisonDamage`、`attribute-panel` 的 baseline）。
- 圣遗物槽位上被换掉的部位标出「新」。
- 这一条替代 `SingleResultWorkbench`。它的全部功能（结果大数字与基准对比、关键面板、五件装备差异与更换、详细伤害表 / 收益曲线 / 装备设置入口、评分模式与评分依据插槽）都要在新视图里有对应位置，做完后删除该组件和 `single-result-workbench.css`。
- 新评分开启时配装完成后自动开始评分的行为保持。

### 8. 手机

- 宽度在页面容器 820px 以下时单列：顶部条吸顶（手机站点顶栏下方，`top: 48px`），角色卡改为立绘在上、信息在下，伤害卡技能列表改成横向滚动的分组标签。
- 抽屉从底部升起，高度占满可视区，底部留出安全区，不被底部导航挡住。
- 顶部条在窄屏只留预设、配装目标、自动配装，账号导入和我的角色收进预设按钮的下拉菜单。

### 9. 文案

以下文字 2026-11-15 随样稿由开发者确认：「自动配装」「配装目标」「计算条件」「全部属性 · 收益曲线」「更换」「添加」「选择」「修改」「伤害明细」「期望伤害」「暴击」「不暴击」「配装设置」「配装结果」「对比候选」「恢复原装备」「新」。抽屉标题用区块名（角色、武器、圣遗物、全部属性、BUFF、队友、敌人、配装设置）。条件卡摘要格式：「角色 n · 武器 n · 圣遗物 n」「未选队友预设 / <预设名>」「Lv <等级> · 全元素抗性 <n>% · <附魔或无附魔>」。其他新文字先问开发者。

## Testing Decisions

- 计算结果不变是首要验证：同一组输入（默认安柏 + 冬极白星，以及一个有 BUFF、有圣遗物的合成预设）改版前后的期望伤害和面板数值一致。
- 读页面源码的现有测试（见「给执行者」）保持通过；如果某个函数确实需要移动，同一次改动里更新测试读取的位置，断言内容不变。
- `tests/direct-reactions-only-7108.test.mjs` 会编译 `NewArtifactPlanPage.vue`、`DamagePanel.vue` 等模板，新组件拆出后它仍要通过。
- 每个任务在浏览器里实测对应区块：桌面 1440 宽和手机 375 宽、浅色和深色各看一次。
