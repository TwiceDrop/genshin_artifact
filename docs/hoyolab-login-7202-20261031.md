## 本次实现

- `MiyousheImport.vue` 提供“使用米游社登录／使用 HoYoLAB 登录”两个按钮。国服继续走原二维码；海外打开官方网页，用户登录后点击窗口底部“完成登录”。已有账号的添加／更新也使用这两个入口。同步失败保留具体错误及已保存凭据。
- Windows：`installer/HoyolabLogin.cs` 用 WebView2 打开 `https://www.hoyolab.com/home`，独立 profile 位于本机凭据目录下；只回收 HoYoLAB 域中的既有凭据字段，经子进程私有 stdout 管道交给 `server/hoyolab-web-login.mjs`，由原 DPAPI 库保存。没有通过 URL、日志或前端 API 返回 Cookie。构建命令 `powershell -NoProfile -File script/build-hoyolab-login.ps1`；运行依赖在 `runtime/hoyolab-login/`。后续正式打包需包含此目录及 WebView2 依赖并履行对应许可，当前未打包发布。
- Android：`MonaLocalPlugin.java` 增加原生官方 WebView 登录／取消，结果经 Capacitor 本地桥接进入原加密库；未禁用证书校验或扩大为任意域名网络入口。

## 用户实测后：安全检查页卡住的修复

用户停在“正在检测您的账号安全”。只读窗口状态确认当前页为 `https://account.hoyolab.com/single-page/cross-login.html?complete=1`。读取该官方公开入口引用的 [crossLogin_597ea40795f6b44d752e.js](https://account.hoyolab.com/single-page/crossLogin_597ea40795f6b44d752e.js)，确认 complete 分支等待 1500ms 后调用 `window.parent.opener.postMessage({type:"syncLoginStatusCallback"},"*")`。

根因：`installer/HoyolabLogin.cs` 原 `NewWindowRequested` 处理把新窗口请求设置为 Handled，再导航原 WebView。原登录页及 opener 关系因此被破坏，官方回调无法回到原页。修复删除该处理，使用 WebView2 默认弹窗行为；不改官方脚本、不跳过安全验证、不清 Cookie／账号数据。当前仅修 Windows 此条已确认调用链，Android 不以此结果宣称已实测。

验证范围仅两项：

1. 使用同一登录宿主源码的修前／修后副本，启动地址及 profile 替换为独立本地合成页面。页面模拟 `window.open` 和官方同名 postMessage 回调。修前原页面被替换并显示“opener 为空：回调失败”；修后子窗口回传，原页面显示“回调成功，原登录页面仍在”。原生辅助功能树曾返回旧标题，最终以实际窗口截图确认结果，未放宽回调条件。
2. 重新编译正式 Windows 登录宿主成功，更新 `runtime/hoyolab-login/HoyolabLogin.exe`。结束卡住的旧窗口后可从原 `http://127.0.0.1:56727/#/uid-data` 再次发起登录，无需更换端口或重置服务。

证据：`.build-target/hoyolab-popup-20261031/` 包含改前源码、合成页面、修前失败文本、修后截图与编译日志。本轮未进行真实账号认证，也未改网页业务、README、版本、WASM或发布；是否完成官方真实登录由用户重试确认。
