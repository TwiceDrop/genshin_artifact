# 5.33.58 与 7.1.11 适配问题和功能特色复核

日期：2026-10-23。比较对象仍为用户提供的 5.33.58 安装包和原 7.1.11 源码／运行内核。

**本轮新确认两处沃雅妮莎相关的计算漏算，以及一处关联预设的默认配置问题。** 对方更值得借鉴的是完整的技能与参数查询、按角色用途设置快捷目标、扫描工具的集成体验。主题与历史分析页面是功能差异，不代表计算更准确。沃雅妮莎六命保持 25% 正确，不跟随对方的 30%。

本轮没有改业务代码。只复核、列问题并保存合成证据；历史暂缓事项不恢复。7.1.12 已另行增加沃雅妮莎最大生命默认目标，该后续改动不算作 7.1.11 已有功能，也不属于本轮修改。

## 已确认的漏算

### 后台角色没有吃到沃雅妮莎的普通水冰定额加值

角色规则中的领唱作用于前台，重唱／Chorus 作用于后台角色；后台角色仍有对应次数和相同的加值效果。只有领唱受益者在前台，不代表整个天赋只能给前台使用。参见 [HoYoWiki 的伤害规则条目](https://wiki.hoyolab.com/pc/genshin/entry/5654) 和 [角色天赋资料](https://www.prydwen.gg/genshin-impact/characters/vodyanitsa)。

7.1.11 的 [VODYANITSA_SUPPORT_RULES](D:/Documents/ChatGPT/v7.1.11/source/beta-data/scoped-character-effect-rules.mjs:20) 把普通水／冰定额加值限制为 `damage && relevant && ordinary && on`。界面中的 `on_field` 确实表示“目标角色在场”。当目标在后台时，这项加值整个被过滤。

用芙宁娜的乌瑟勋爵攻击进行定向复现，双方使用相同零命、90 级、10 级天赋、1 级学徒笔记，无圣遗物，敌人 90 级、各抗性 10%。沃雅妮莎来源生命设为 65000，普通水冰模式，且假定有尚未消耗的有效重唱次数：

| 条件 | 本项目期望伤害 | 实际定额 |
| --- | ---: | ---: |
| 不加沃雅妮莎天赋 | 915.525001 | 0 |
| 加天赋，目标前台 | 2866.485376 | 3500 |
| 加天赋，目标后台 | 915.525001 | 0 |
| 对方包内相同攻击及天赋输入 | 2866.485376 | 3500 |

这个无其他前后台差异的样本，后台应继续获得定额，却退回无 BUFF 结果，属于明确漏算。不是所有后台伤害都应加：仍须满足元素／反应模式、有效次数和持续时间。

同类前台限定还出现在沃雅妮莎自身扩展的普通水伤 A4 处理，以及薇斯纳专用的沃雅妮莎星扩散定额路径。本轮数值确认集中在普通水伤受益者，不把这些静态线索扩写为所有角色、所有伤害分支都已复现。

建议优先修正公共作用域规则，区分前台领唱与后台重唱；不要为了出数而谎报目标站在前台，否则会连带错误启用其他真正限定前台的效果。

### 自动关联把天赋次数效果错误绑定到歌声状态

天赋的两类次数效果独立持续 30 秒，施放战技时刷新；零命战技的歌声状态为 16 秒。因而“歌声已结束，但还有未过期且未消耗的次数”是合法状态。资料见 [角色战技与天赋](https://www.prydwen.gg/genshin-impact/characters/vodyanitsa)。

单人计算器的队友预设关联会调用 [deriveTeamBuffs](D:/Documents/ChatGPT/v7.1.11/source/beta-data/hybrid-team-optimizer.mjs:105)，其中只有 `p.song_active && a4_active` 时才生成 `VodyanitsaA4`。

对实际 `deriveSingleTeamContext` 做了两次合成调用：固定同一来源面板，保留“领唱／重唱已触发”为开启，只切换“歌声状态”。歌声开启时生成 A4，关闭后生成列表为空，且没有提示仍有效的次数无法表达。这会遗漏上述剩余次数期间的加值。

范围限定为**自动关联队友的 BUFF 生成路径**；手动添加 A4 不经过这里的歌声条件。建议分别表达歌声、天赋次数有效状态，不能全局取消所有歌声条件，因为六命等其他效果确实有各自条件。

## 已确认的默认配置问题

### 专武装备者在后台会让关联预设默认漏启用对前台的加攻

这项是配置语义混用，不能笼统说“专武后台完全不生效”。

角色预设中，漩流颂歌的 `on_field` 标签是“装备者在场（自身获得加攻；后台仍可叠生命）”。但 [createTeamContextSource](D:/Documents/ChatGPT/v7.1.11/source/src/algorithms/single-team-context.mjs:26) 直接用这个值初始化 `signatureOnField`，而关联队友界面把后者显示为 [“专武对当前角色生效”](D:/Documents/ChatGPT/v7.1.11/source/src/pages/NewArtifactPlanPage/NewArtifactPlanPage.vue:589)。

两者不是同一个条件：来源装备者在后台，不等于当前前台受益者不能吃加攻。武器材料明确允许装备者在后台触发，受益者为当前场上角色。可对照 [本项目保存的正式分支原文](D:/Documents/ChatGPT/v7.1.11/source/beta-data/sources-release-71/14524.html) 及 [HoYoWiki 武器条目](https://wiki.hoyolab.com/pc/genshin/entry/11729?lang=en-us)。

复现使用生命超过上限阈值的合成沃雅妮莎预设，精一漩流颂歌、三层、强化状态，受益薇斯纳明确在前台：

| 新关联预设的情况 | 自动生成专武 BUFF | 薇斯纳攻击力 |
| --- | --- | ---: |
| 来源预设“装备者在场”开启 | 是 | 557.96 |
| 来源预设“装备者在场”关闭 | 否 | 399.62 |
| 来源为后台，但手动打开关联区“专武对当前角色生效” | 是 | 557.96 |

因此，问题是新建关联时默认继承了错误语义，用户手动开启受益开关即可恢复。不能把用户主动关闭该开关也算成程序漏算。应保留“来源是否站场”“受益者是否站场”“效果是否满足条件”各自含义。

上述三个相关文件与当前 7.1.12 直接字节比较一致，所以其新加的最大生命目标不会顺带消除这些问题；没有对 7.1.12 另做运行验证或修改。
